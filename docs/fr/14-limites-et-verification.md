# Limites et vérification documentaire

Base lue : OpenZeppelin Contracts, commit `bbf3600dc2fd09c7409c5e9d65e2faea36f35115`. `master` est une branche de développement, pas une garantie de release auditée.
Cette reprise publie uniquement de la documentation : aucune nouvelle installation, compilation ou exécution. Une préparation antérieure à cette méthode a utilisé de l'outillage local ; elle ne constitue pas un audit.
Les [tests du dépôt](../../test/token) décrivent les cas à vérifier. Les wrappers `$ERC20`, etc., servent aux tests et ne sont pas des modèles à déployer.
Les chapitres couvrent les mécanismes cités, pas tous les ERC ni toutes les combinaisons d'extensions. Mise à niveau de contrats, tokens confidentiels et déploiement demandent des parcours dédiés.
Consulter le [README original](../../README.md) et les versions publiées avant une intégration.
